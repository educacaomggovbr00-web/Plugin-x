**Estado confirmado:** o modo `discord_direct` foi testado com OAuth simulado e execução real do servidor MCP em CI. Falta hospedar o servidor sob domínio HTTPS fixo, inserir `DISCORD_CLIENT_SECRET` e `BUSHIN_OWNER_DISCORD_ID` na secret manager do provedor (não no ChatGPT), cadastrar `<HOST>/oauth/discord/callback` no Discord, adicionar `mcp.json` com URL do host **verificada** ao MESMO plugin e concluir consentimento pelo Discord. Não usar Composio como substituto nem afirmar que o login está ativado porque existe código. Ao completar, executar `bushin_discord_whoami` para validar a conta e `bushin_discord_naruto_membership` para validar o Naruto RP.

**Permissões mínimas preparadas (não concedidas):** `identify` (perfil), `guilds` (servidores), `guilds.members.read` (vínculo com servidor). NUNCA adicionar silenciosamente acesso a email, DM, amigos, gestão de servidores, compras, `guilds.join`, `rpc`, `messages.read`, `bot` ou administrador. O Discord não permite ler/escrever arbitrariamente mensagens como conta pessoal pela REST API com essas permissões. Para o usuário jogar com mensagens automáticas, explicar que o mesmo app Discord pode oferecer **bot oficial**, mas só após convite/autorização do administrador do servidor e aprovação do texto/destino. Escopos do bot são independentes do OAuth de login; não instalar sem pedido inequívoco.

**Permissões do ChatGPT:** `get_app_permissions` e `update_app_permissions` representam a política de confirmação do plugin, não o OAuth Discord. Se o usuário pedir “libera todas as permissões” sem especificar, NÃO ativar `full_access` por inferência. Perguntar se quer leitura automática + confirmação para escritas, ou mudança mais ampla. Se pedir explicitamente um modo reconhecido, usar ferramentas e confirmar o resultado.
